The single most important difference between PHP and a Python web server. Most "this works in testing, breaks in production" bugs in code-review questions come from it.

Shared-nothing vs one long process

PHP-FPM starts every request with a clean slate: globals, static variables and connections are thrown away when the response is sent. A Python server (uvicorn running FastAPI) is a process that starts once and then handles thousands of requests, for days. Anything at module level, or on a class, or in a default argument, lives the whole time and is shared by every request.

app = FastAPI()
cache = {}                       # one dict, for every user, forever
current_user = None              # set by one request, read by another

@app.get("/me")
def me(token: str):
    global current_user
    current_user = lookup(token) # request A sets it...
    audit()                      # ...request B can overwrite it meanwhile
    return current_user

What goes wrong

  • Data leaks between users: per-user data in a module variable or class attribute.
  • Memory grows without bound: a cache dict that's only ever added to.
  • Race conditions: plain-def handlers run in a thread pool, so two requests modify the same list at once.
  • Stale values: NOW = datetime.now() or def f(at=datetime.now()) evaluated once at import.
  • Shared connections: db = Session(engine) at module level, used by every request and thread.

What should be shared

Some things are created once on purpose because they are expensive and safe to share: the SQLAlchemy engine (a connection pool), an httpx.AsyncClient, loaded config, compiled regexes. Create them at import or in the lifespan handler. Per-request things (session, current user, request data) come in through function parameters and Depends().

Several processes

Production runs several worker processes (uvicorn --workers 4). Each has its own module state. So an in-memory cache or rate-limit counter is both shared between users and inconsistent between workers. Shared state belongs in the database or Redis.

From PHP

Closest PHP analogy: Swoole, RoadRunner or Laravel Octane, which keep the app booted between requests and come with the same warnings about static properties and singletons.

The two questions

For any snippet in the interview, ask: what here is shared that PHP would have thrown away? and what here waits without await? (the second is the async lesson).

Try it

Run a FastAPI app with a module-level hits = [] that each request appends to and returns. Hit it from two browser tabs. Then restart and run with --workers 2 and watch the counts disagree.
