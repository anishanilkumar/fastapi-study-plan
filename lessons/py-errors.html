Python reports problems with exceptions, everywhere. Reading code well means knowing what can raise, what's caught, and what gets cleaned up.

try / except / else / finally

try:
    n = int(raw)
except ValueError:
    n = 0                        # only what you expect, nothing else
except (TypeError, KeyError) as e:
    log.warning("bad input: %s", e)
    raise                        # re-raise the same exception
else:
    print("parsed", n)           # runs only if nothing was raised
finally:
    cleanup()                    # runs always, even on return or raise

Raising

if amount < 0:
    raise ValueError(f"amount must be positive, got {amount}")

class DeviceNotFound(Exception):
    """Raised when a serial isn't registered."""

try:
    resp = client.get(url)
except httpx.HTTPError as e:
    raise UpstreamError("vendor API failed") from e   # keeps the cause

Custom exceptions subclass Exception. Name them for what went wrong, not where.

Why bare except is bad

try:
    process(job)
except:            # or: except Exception: pass
    pass

This swallows every error: typos (NameError), bugs (AttributeError), and with bare except: even Ctrl-C and shutdown (KeyboardInterrupt, SystemExit). The job silently does nothing and nobody knows. If you truly must catch everything at a boundary, catch Exception and log it with the traceback: log.exception("job failed").

Context managers: with

A with block guarantees cleanup, like a built-in finally.

with open("data.csv", encoding="utf-8") as f:
    rows = f.readlines()
# file is closed here, even if readlines raised

with Session(engine) as session:
    ...                      # session closed at the end

with httpx.Client() as client, open("out.json", "w") as out:
    ...                      # several at once

You can write your own with contextlib.contextmanager: code before yield is setup, after it is teardown. FastAPI's Depends with yield uses the same idea.

from contextlib import contextmanager

@contextmanager
def timer(label):
    start = time.perf_counter()
    try:
        yield
    finally:
        print(label, time.perf_counter() - start)

EAFP

Python style is "easier to ask forgiveness than permission": try it and handle the exception, rather than checking first. It also avoids races, e.g. insert and catch IntegrityError instead of "check, then insert".

From PHP

Like PHP's try/catch/finally, with except for catch. Python has no warnings-vs-exceptions split: d["missing"], int("x"), open("nope") all raise, where PHP might return null/false with a notice.
