Async lets one thread juggle many requests that spend most of their time waiting on the network. It only works if nothing blocks the thread.

The event loop

An async def function returns a coroutine. The event loop runs one coroutine at a time on one thread. When it hits await on something that waits (a socket read, a sleep), it pauses there and the loop runs another coroutine. Switching happens only at await.

import asyncio, httpx

async def fetch(client, url):
    r = await client.get(url)          # pauses here; others run meanwhile
    return r.status_code

async def main():
    async with httpx.AsyncClient() as client:
        codes = await asyncio.gather(  # run all three at once
            fetch(client, "https://a.example"),
            fetch(client, "https://b.example"),
            fetch(client, "https://c.example"),
        )
    print(codes)

asyncio.run(main())

Three one-second requests take about one second total, not three.

Blocking calls freeze everything

Code that waits without await holds the only thread. While it waits, no other request on that worker makes progress.

Blocking (don't use in async def)Non-blocking
time.sleep(1)await asyncio.sleep(1)
requests.get(url)await httpx.AsyncClient().get(url)
sync DB driver (psycopg2, sqlite3, Session)async driver (asyncpg, AsyncSession)
CPU-heavy loop, big file readawait asyncio.to_thread(fn)
@app.get("/report")
async def report():
    data = requests.get(VENDOR_URL).json()   # BUG: blocks the event loop
    return data

One slow vendor call now stalls every other endpoint on that worker, even /health. This is the classic async review question.

Trap

await requests.get(url) doesn't make it async; it's a TypeError because a Response isn't awaitable. And forgetting await on a coroutine (client.get(url) without it) gives you a coroutine object instead of a response, plus a "was never awaited" warning.

Tasks

task = asyncio.create_task(send_email(user))   # starts now, in the background
...
await task                                      # wait for it later

async with asyncio.TaskGroup() as tg:           # 3.11+: structured, cancels on error
    tg.create_task(a())
    tg.create_task(b())

await asyncio.wait_for(fetch(c, url), timeout=5)

Keep a reference to tasks you create; a task with no reference can be garbage-collected mid-run.

Async vs threads vs processes

Async: many waiting I/O jobs, one thread. Threads: also for I/O, works with blocking libraries, but limited by the GIL for CPU. Processes (multiprocessing, more uvicorn workers): real CPU parallelism.

From PHP

PHP-FPM handles concurrency with many processes, each blocking freely. In async Python, one process serves many requests at once, so a single blocking call hurts everyone, not just its own request. Closest PHP relatives: ReactPHP, Amp, Swoole coroutines.
