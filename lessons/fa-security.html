Authentication, password storage, tokens and the browser-facing settings. Most review findings in API code are here.

Passwords

from pwdlib import PasswordHash          # what the FastAPI docs use now
hasher = PasswordHash.recommended()      # argon2

hash_ = hasher.hash(password)            # store this
hasher.verify(password, hash_)           # True / False

Never store plain or fast-hashed (MD5, SHA-256) passwords. bcrypt is also fine. Return the same error for "no such user" and "wrong password".

Bearer tokens

from fastapi.security import OAuth2PasswordBearer
oauth2 = OAuth2PasswordBearer(tokenUrl="token")   # also adds an Authorize button to /docs

def current_user(token: Annotated[str, Depends(oauth2)], db: DB) -> User:
    try:
        payload = jwt.decode(token, SECRET_KEY, algorithms=["HS256"])
    except jwt.InvalidTokenError:
        raise HTTPException(401, "invalid token", headers={"WWW-Authenticate": "Bearer"})
    user = db.get(User, int(payload["sub"]))
    if user is None:
        raise HTTPException(401, "invalid token", headers={"WWW-Authenticate": "Bearer"})
    return user
  • JWTs (PyJWT): always pass algorithms=[...] explicitly; set an exp; keep the secret out of the code (env var).
  • Opaque tokens (random strings in the DB) are simpler and revocable. Store a hash of the token and compare with hmac.compare_digest.
  • API keys from headers: compare with compare_digest, never ==.

Authorization: the IDOR check

# BUG: any logged-in user can read any device
device = db.get(Device, device_id)

# fix: scope by owner in the query
device = db.scalar(select(Device).where(Device.id == device_id,
                                        Device.owner_id == user.id))
if device is None:
    raise HTTPException(404)

mTLS / client certificates

With client-cert auth, TLS is usually terminated at nginx, which verifies the cert and forwards details in headers (e.g. X-SSL-Client-Verify, the subject DN). The app must trust those headers only from the proxy, and nginx must strip any client-supplied copies; otherwise anyone can send X-SSL-Client-Verify: SUCCESS.

CORS

app.add_middleware(
    CORSMiddleware,
    allow_origins=["https://portal.example.com"],   # not ["*"] with credentials
    allow_credentials=True,
    allow_methods=["GET", "POST"],
    allow_headers=["Authorization", "Content-Type"],
)

CORS only controls which browser origins may read responses. It isn't authentication, and doesn't stop curl.

Other checks

  • SQL: bound parameters only (database lesson).
  • Secrets from env/config, never committed; don't log them.
  • Limits: max page size, max body size, rate limiting on login.
  • Error bodies: no stack traces or internal details.
  • Uploaded filenames and paths: never trust them.
From PHP

password_hash/password_verify → pwdlib/bcrypt. Sanctum/Passport tokens → OAuth2PasswordBearer + JWT or DB tokens. Policies → an explicit owner check in each query or a dependency.
