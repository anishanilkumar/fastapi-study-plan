How FastAPI runs your handlers, and how to share expensive clients safely. Read the Python async lesson first.

async def or def?

  • async def handlers run directly on the event loop. Fast, but everything inside must be non-blocking (await-based).
  • plain def handlers run in a thread pool (about 40 threads by default), so blocking code there doesn't freeze the loop.
@app.get("/a")
async def a():
    await asyncio.sleep(1)         # fine

@app.get("/b")
def b():
    time.sleep(1)                  # fine: runs in a worker thread

@app.get("/c")
async def c():
    time.sleep(1)                  # BUG: blocks every request on this worker

Rule of thumb: if you use a sync library (sync SQLAlchemy, requests, sqlite3), write plain def. If everything you call is async, write async def. Dependencies follow the same rule.

Two fixes for a blocking call in async code

# 1. Use an async library
async def report():
    r = await app.state.http.get(VENDOR_URL)

# 2. Make the handler plain def (or push the call to a thread)
def report():
    r = httpx.get(VENDOR_URL)

async def report():
    r = await asyncio.to_thread(httpx.get, VENDOR_URL)

Trade-off: async scales to many concurrent waits on one thread; the thread pool is simpler and works with any library but caps at ~40 concurrent blocking calls per worker, after which requests queue.

Lifespan: create once, close once

from contextlib import asynccontextmanager

@asynccontextmanager
async def lifespan(app: FastAPI):
    app.state.http = httpx.AsyncClient(timeout=10)   # startup
    yield
    await app.state.http.aclose()                    # shutdown

app = FastAPI(lifespan=lifespan)

def get_http(request: Request) -> httpx.AsyncClient:
    return request.app.state.http

One client means a shared connection pool; creating httpx.AsyncClient() per request throws that away (and leaks if not closed). Same for the DB engine.

Always set timeouts

httpx defaults to 5 s; requests has no timeout by default and can hang forever. Every outbound call in a server needs one.

Background tasks

from fastapi import BackgroundTasks

@app.post("/signup", status_code=201)
def signup(body: UserIn, tasks: BackgroundTasks):
    user = create_user(body)
    tasks.add_task(send_welcome_email, user.email)   # after the response is sent
    return user

Fine for small fire-and-forget work. It runs in the same process, so it's lost if the process restarts; anything important belongs in a real queue (Celery, RQ, arq).

Streaming

StreamingResponse(generator()) sends a large or slow response piece by piece. Server-sent events and big CSV exports use it.

From PHP

Laravel's queued jobs vs dispatch()->afterResponse() is the same split as a real queue vs BackgroundTasks. Service-provider singletons are the lifespan's job.

Trap

An async def endpoint using sync SQLAlchemy Session blocks the loop on every query. Either plain def with Session, or async def with AsyncSession and an async driver. Mixing is the bug.

Try it

Make two endpoints, one async def with time.sleep(3) and a /health. Call the slow one, then /health immediately. Fix it both ways and repeat.
