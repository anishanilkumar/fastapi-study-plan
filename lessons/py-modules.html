How code is split across files and how Python finds it. This matters as soon as a FastAPI app grows past one file.

Modules

Every .py file is a module. Importing runs the file once and caches it; later imports get the same module object.

# utils.py
def slugify(s): ...

# main.py
import utils
utils.slugify("Hi there")

from utils import slugify          # import one name
from utils import slugify as slug  # rename
import datetime as dt

Avoid from x import *: readers can't tell where names came from.

Packages

A folder of modules is a package. An __init__.py file marks it (and can be empty). Typical FastAPI layout:

app/
  __init__.py
  main.py          # app = FastAPI(), includes routers
  db.py            # engine, get_db()
  models.py        # SQLAlchemy models
  schemas.py       # Pydantic models
  routers/
    __init__.py
    devices.py
tests/
  test_devices.py
pyproject.toml
from app.db import get_db                 # absolute import (preferred)
from .schemas import DeviceIn             # relative, inside the package

Where Python looks

Imports are resolved through sys.path: the directory of the script you ran (or the current directory with -m), then the venv's site-packages. Run apps as modules from the project root (python -m app.main, uvicorn app.main:app) so app is importable.

Trap

Naming your own file json.py, random.py or fastapi.py shadows the real library: import json imports yours. Also avoid circular imports (a imports b imports a); move shared code into a third module.

Module-level code runs once

Anything at the top level of a module runs at import time, once per process. That's where constants, the app object and the engine live. It's also why module-level mutable state is shared by every request in a server (see the lesson on long-running processes).

Installing and pinning

Add dependencies to pyproject.toml, install into the venv, and use a lock file (uv lock, or pip freeze > requirements.txt) so deploys get the same versions.

From PHP

namespace App\Models; use App\Models\User; is the folder app/models.py and from app.models import User. There's no autoloader: the import statement does the loading, and the file path is the namespace.

Try it

Make a package shop/ with prices.py (a with_vat(amount) function) and main.py that imports it. Run it with python -m shop.main from the parent folder, then try python shop/main.py and read the error.
