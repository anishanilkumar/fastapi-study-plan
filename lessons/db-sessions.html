Most database bugs in API code are about the session's lifetime, transactions, and doing in Python what the database should do.

One session per request

# BUG: one session shared by every request and every thread
db = Session(engine)

@app.get("/devices")
def list_devices():
    return db.scalars(select(Device)).all()

A Session isn't thread-safe and holds a transaction and an identity map. Shared, it mixes requests' changes, serves stale objects, and after one error breaks for everyone.

# fix
def get_db():
    with Session(engine) as session:
        yield session

DB = Annotated[Session, Depends(get_db)]

Transactions and the failed state

A session opens a transaction on first use. commit() ends it; on an exception you must rollback(). If not, every later use raises "This Session's transaction has been rolled back due to a previous exception during flush" (PendingRollbackError).

with Session(engine) as session, session.begin():   # commits, or rolls back on error
    session.add(a)
    session.add(b)

With a per-request session closed in get_db, a failed request's session is thrown away, which is another reason not to share one.

Uniqueness: let the database enforce it

# BUG: race. Two requests both see "not exists", both insert.
if db.scalar(select(Device).where(Device.serial == body.serial)):
    raise HTTPException(409, "serial already registered")
db.add(Device(**body.model_dump())); db.commit()

# fix: unique constraint + catch the error
from sqlalchemy.exc import IntegrityError
db.add(Device(**body.model_dump()))
try:
    db.commit()
except IntegrityError:
    db.rollback()
    raise HTTPException(409, "serial already registered")

The pre-check can stay for a friendly message, but the constraint is what guarantees it.

Lost updates

Read-modify-write (acct.balance = acct.balance - amount) loses updates under concurrency. Do it in SQL (update(Account).values(balance=Account.balance - amount)), lock the row (select(...).with_for_update()), or use a version column.

N+1 queries

owners = db.scalars(select(Owner)).all()           # 1 query
for o in owners:
    print(len(o.devices))                          # +1 query per owner (lazy load)

from sqlalchemy.orm import selectinload
owners = db.scalars(select(Owner).options(selectinload(Owner.devices))).all()   # 2 queries total

Also: every list endpoint needs a limit. select(Device) with no limit is a time bomb.

Ownership in the query

# BUG: loads anyone's device, filters in Python (or not at all)
device = db.get(Device, device_id)

# fix
device = db.scalar(select(Device).where(Device.id == device_id,
                                        Device.owner_id == user.id))

Filtering after loading also breaks pagination and counts. For multi-tenant apps, every query gets the tenant filter.

From PHP

The same rules as Doctrine (one EntityManager per request, closed after an exception) and Eloquent (with() for N+1, lockForUpdate(), unique indexes over exists() checks). The difference: PHP got a fresh EntityManager per request for free.

Try it

Write POST /devices with a unique serial. Make it fail on a duplicate without catching the error, then call another endpoint on the same (deliberately shared) session to see PendingRollbackError. Then fix both properly.
