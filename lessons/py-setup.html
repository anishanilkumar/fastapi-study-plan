Before any syntax: how to run Python, and how to keep one project's packages away from another's. Get this right once and every later lesson is just typing into a file and running it.

Which Python

macOS ships a python3, but install your own (Homebrew brew install python, or let uv manage versions). Check with python3 --version. Anything 3.11 or newer is fine for this course; FastAPI and SQLAlchemy 2.0 need 3.8+, and the str | None type syntax needs 3.10+.

The REPL

Type python3 with no arguments and you get an interactive prompt. Use it constantly while reading: paste each example, change it, see what happens.

>>> 7 // 2
3
>>> "abc".upper()
'ABC'
>>> help(str.split)      # docs for anything
>>> dir([])              # what methods does a list have?

Virtual environments

A virtual environment (venv) is a folder holding a private copy of the interpreter plus the packages one project needs. Without it, pip install puts packages into the global Python and projects start fighting over versions.

python3 -m venv .venv            # create it, once per project
source .venv/bin/activate        # use it in this shell
pip install httpx                # installs into .venv only
python -c "import httpx; print(httpx.__version__)"
deactivate                       # leave it

uv is a much faster tool that does the same job and also manages Python versions:

uv venv                          # makes .venv
uv pip install "fastapi[standard]"
uv run python main.py            # runs inside .venv without activating
From PHP

A venv is vendor/, and pip/uv is Composer. The difference: PHP finds vendor/ through require 'vendor/autoload.php'; Python finds packages through whichever interpreter you run, so you must run the venv's python (activate, or uv run).

Running a script

# hello.py
def main():
    name = input("Name? ")
    print(f"Hello, {name}")

if __name__ == "__main__":
    main()

python3 hello.py runs it. The if __name__ == "__main__": guard means "only when run directly, not when imported". You'll see it at the bottom of most scripts (this site's app.py uses it to start the server).

Dependencies in a project

Modern projects list dependencies in pyproject.toml (like composer.json). Older ones use requirements.txt, a plain list you install with pip install -r requirements.txt.

[project]
name = "notes-api"
requires-python = ">=3.11"
dependencies = ["fastapi[standard]", "sqlalchemy>=2"]
Try it

Make a folder, create a venv, install httpx, and write a script that prints the status code of httpx.get("https://example.com"). Then delete .venv and watch the import fail.
