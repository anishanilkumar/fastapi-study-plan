Type hints don't change how Python runs; they are read by your editor, by type checkers like mypy, and crucially by FastAPI and Pydantic, which use them to parse and validate requests.

The basics

def find_user(user_id: int, include_deleted: bool = False) -> User | None:
    ...

names: list[str] = []
scores: dict[str, int] = {}
point: tuple[float, float] = (0.0, 0.0)
row: tuple[int, ...]            # any length
ids: set[int]

Read User | None as "a User, or None". Older code writes it Optional[User] (from typing); same meaning. Union[int, str] is int | str.

More you'll see

from typing import Any, Literal, Annotated, TypedDict
from collections.abc import Callable, Iterable, Iterator

Status = Literal["active", "revoked"]          # only these strings
def apply(fn: Callable[[int], str], xs: Iterable[int]) -> list[str]: ...
def stream() -> Iterator[bytes]: ...           # a generator

class UserRow(TypedDict):                      # a dict with known keys
    id: int
    email: str

Limit = Annotated[int, Query(ge=1, le=100)]    # FastAPI: type + metadata

Any turns checking off for that value. Annotated[T, extra] is "type T, plus extra info for whoever reads it"; FastAPI reads the extra to know it's a query parameter with limits.

Generics (3.12 syntax)

def first[T](items: list[T]) -> T | None:
    return items[0] if items else None

Hints are not enforced at runtime

def double(x: int) -> int:
    return x * 2

double("ab")    # 'abab', no error

Plain Python ignores hints. Errors are caught by a checker (mypy, pyright) before running, or by Pydantic at the API edge, which does enforce and convert.

Why this matters for FastAPI

@app.get("/devices/{device_id}")
def get_device(device_id: int, verbose: bool = False) -> DeviceOut:
    ...

From these hints alone FastAPI knows: device_id comes from the path and must parse as int (else 422), verbose is an optional query param (?verbose=true), and the response is filtered through DeviceOut. Reading hints fluently is reading the API.

From PHP

Similar to PHP's typed parameters (?User is User | None), but PHP enforces them at runtime and Python doesn't. Generic types like list[str] are what PHPStan's @param array<string> docblocks try to say.

Try it

Add hints to a small function you wrote earlier, install mypy in your venv, and run mypy file.py. Then call it with a wrong type and see mypy catch what Python doesn't.
