Iterators and generators let you process data one item at a time, so a 10 GB log file or an endless stream doesn't need to fit in memory.

Iterables and iterators

Anything you can for over is an iterable (list, dict, str, file, range). An iterator produces items one at a time and is used up once consumed.

it = iter([1, 2, 3])
next(it)   # 1
next(it)   # 2
list(it)   # [3]
list(it)   # []  ← exhausted

Generators

A function containing yield returns a generator: it runs until yield, hands out a value, and pauses until asked for the next.

def read_lines(path):
    with open(path, encoding="utf-8") as f:
        for line in f:
            if line.strip():
                yield line.rstrip("\n")

for line in read_lines("big.log"):    # one line in memory at a time
    if "ERROR" in line:
        print(line)

Generator expressions

Like a list comprehension in round brackets: lazy, no list built.

total = sum(len(line) for line in read_lines("big.log"))

Pipelines

def parse(lines):
    for line in lines:
        ts, level, msg = line.split(" ", 2)
        yield {"ts": ts, "level": level, "msg": msg}

errors = (r for r in parse(read_lines("app.log")) if r["level"] == "ERROR")
for r in itertools.islice(errors, 10):   # first 10 only; rest never read
    print(r)

itertools

islice (take n), chain (concatenate), groupby (consecutive groups; sort first), batched (3.12: chunks of n), count, pairwise. Worth a skim.

Trap

A generator can be iterated only once. rows = (r for r in data), then len(list(rows)) followed by for r in rows loops over nothing. If you need it twice, make a list.

Where you'll meet them in FastAPI

Dependencies with yield (the DB session) are generators: setup before, cleanup after. StreamingResponse takes a generator to stream a big download. Lifespan is an async generator.

From PHP

PHP has generators with the same yield keyword and the same idea. Python just uses them far more, and its built-ins (sum, any, zip, map) all accept them.
