The basic values, and the two comparisons that trip up PHP developers: truthiness and is.

Numbers

int has no size limit (2 ** 100 just works). float is a 64-bit double with the usual rounding (0.1 + 0.2 != 0.3); use decimal.Decimal for money. Convert with int("42"), float("3.5"); a bad string raises ValueError instead of quietly becoming 0.

Strings

Strings are Unicode and immutable: every method returns a new string.

name = "Asha"
f"Hello {name}, you have {3 * 2} items"   # f-string, like "{$name}"
f"{price:.2f}  {count:>5}  {ratio:.0%}"   # formatting inside the braces
f"{user=}"                                # debugging: prints user='...'

"a,b,c".split(",")        # ['a', 'b', 'c']   (explode)
", ".join(["a", "b"])     # 'a, b'           (implode, called on the separator)
"  hi  ".strip()          # 'hi'             (trim)
"report.pdf".endswith(".pdf")
"abc"[0], "abc"[-1]       # 'a', 'c'
len("héllo")              # 5 characters, not bytes

Triple quotes make multi-line strings. b"..." is bytes, a separate type: "é".encode() gives bytes, .decode() goes back. Network and crypto APIs often want bytes.

bool and None

True and False. None is the single "no value" object, Python's null. A function with no return returns None.

Truthiness

In an if, these are all false: False, None, 0, 0.0, "", [], {}, set(), (). Everything else is true (including "0", unlike PHP).

if not items:            # idiomatic "is the list empty?"
    return []

token = os.environ.get("API_TOKEN")
if token is None:        # "was it set at all?"
    raise RuntimeError("API_TOKEN missing")
if not token:            # also catches an empty string
    ...
Trap

A check like if not expected_token or provided == expected_token: allow() fails open: when config is empty, everyone gets in. When reviewing, ask what each check does with None, "" and 0.

is vs ==

== asks "equal value?". is asks "the very same object?". Use is only for singletons: x is None, x is not None. For numbers and strings, is sometimes appears to work because of caching, then breaks with other values; always use ==.

a = [1, 2]; b = [1, 2]
a == b     # True
a is b     # False: two lists

Checking types

type(x) gives the type; isinstance(x, (int, float)) is the right way to check. Python never converts types for you in comparisons or arithmetic: "3" + 4 raises TypeError.

From PHP

No type juggling. "abc" == 0 is false, "10" < "9" compares as strings (true!), and "0" is truthy. Convert explicitly with int() at the edge, which is exactly what FastAPI does for you from type hints.

Try it

In the REPL, evaluate bool() on ten values you think are false. Then write describe(x) returning "missing" for None, "empty" for "", else the value, and test it with None, "", "0".
