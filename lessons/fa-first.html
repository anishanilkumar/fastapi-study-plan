FastAPI is a framework for JSON APIs built on type hints. You write ordinary functions; FastAPI turns their parameters into request parsing, validation and docs.

Install and run

uv venv && source .venv/bin/activate
uv pip install "fastapi[standard]"      # FastAPI + uvicorn + the fastapi CLI
# main.py
from fastapi import FastAPI

app = FastAPI()

@app.get("/")
def root():
    return {"message": "hello"}

@app.get("/items/{item_id}")
def read_item(item_id: int, q: str | None = None):
    return {"item_id": item_id, "q": q}
fastapi dev main.py        # reloads on save; http://127.0.0.1:8000
# or: uvicorn main:app --reload

What just happened

  • app is an ASGI application. uvicorn is the server that speaks HTTP and calls it (like PHP-FPM + nginx calling your index.php).
  • @app.get("/items/{item_id}") registers the function for GET on that path. There's .post, .put, .patch, .delete too.
  • item_id: int is taken from the path and converted to int. /items/abc gets a 422 with a clear error, and your function never runs.
  • Returning a dict (or list, or Pydantic model) is serialised to JSON.

Free docs

Open /docs: interactive Swagger UI generated from your code, where you can call every endpoint. /redoc is another view; /openapi.json is the raw OpenAPI schema. Use /docs constantly while learning.

Order of routes

Routes match in the order they're declared. Put /users/me before /users/{user_id}, or "me" is parsed as an id (and fails as an int).

A whole small API

from fastapi import FastAPI, HTTPException
from pydantic import BaseModel

app = FastAPI()

class NoteIn(BaseModel):
    text: str

class Note(NoteIn):
    id: int

notes: dict[int, Note] = {}      # in memory: fine for practice, shared by all!
next_id = 1

@app.get("/notes")
def list_notes() -> list[Note]:
    return list(notes.values())

@app.post("/notes", status_code=201)
def create_note(body: NoteIn) -> Note:
    global next_id
    note = Note(id=next_id, text=body.text)
    notes[note.id] = note
    next_id += 1
    return note

@app.delete("/notes/{note_id}", status_code=204)
def delete_note(note_id: int) -> None:
    if notes.pop(note_id, None) is None:
        raise HTTPException(404, "note not found")

That's the "Build one" exercise from the plan. Notice the comment: notes and next_id are module-level state, so this is fine for practice and wrong for production (see the long-running process lesson). app.py behind this site is the same shape with SQLite.

From PHP

Like Slim or Laravel's Route::get('/items/{id}', fn(int $id) => ...), but the parameter types drive validation and OpenAPI docs, with no FormRequest classes or annotations.

Try it

Build the notes API above, call every route from /docs, then add PATCH /notes/{id} that changes the text and returns 404 for a missing id.
