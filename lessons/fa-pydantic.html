Pydantic models describe the shape of data and validate it. In FastAPI they define what a request may contain and what a response is allowed to reveal.

A model

from pydantic import BaseModel, Field, EmailStr

class UserIn(BaseModel):
    email: EmailStr                              # needs email-validator
    name: str = Field(min_length=1, max_length=100)
    age: int | None = Field(default=None, ge=0, le=150)
    tags: list[str] = []                         # safe in Pydantic: copied per instance

Pydantic converts where it can ("31" → 31) and rejects what it can't, with a list of every error. In FastAPI, a failure is a 422 response before your function runs.

Validators

from pydantic import field_validator, model_validator

class Booking(BaseModel):
    start: datetime
    end: datetime
    serial: str

    @field_validator("serial")
    @classmethod
    def upper_serial(cls, v: str) -> str:
        return v.strip().upper()

    @model_validator(mode="after")
    def end_after_start(self):
        if self.end <= self.start:
            raise ValueError("end must be after start")
        return self

Input model ≠ output model

Never return your database object or a model that has secret fields. Use separate models and let response_model (or the return annotation) filter the output.

class UserOut(BaseModel):
    id: int
    email: str
    name: str
    model_config = ConfigDict(from_attributes=True)   # read from ORM objects

@app.post("/users", response_model=UserOut, status_code=201)
def create_user(body: UserIn, db: DB):
    user = User(**body.model_dump(), password_hash=hash_pw(...))
    db.add(user); db.commit()
    return user              # has password_hash, but UserOut drops it

With the return annotation -> UserOut you get the same filtering. Without either, FastAPI would serialise whatever you return.

Useful methods

body.model_dump()                       # → dict
body.model_dump(exclude_unset=True)     # only fields the client sent (for PATCH)
body.model_dump_json()
UserOut.model_validate(orm_user)        # build from an object or dict
body.model_copy(update={"name": "x"})

PATCH done right

class UserPatch(BaseModel):
    name: str | None = None
    age: int | None = None

@app.patch("/users/{user_id}")
def patch_user(user_id: int, body: UserPatch, db: DB) -> UserOut:
    user = get_or_404(db, user_id)
    for field, value in body.model_dump(exclude_unset=True).items():
        setattr(user, field, value)
    db.commit()
    return user

exclude_unset tells "not sent" apart from "sent as null".

Extra fields and mass assignment

By default unknown fields are ignored. model_config = ConfigDict(extra="forbid") rejects them. Never accept fields like is_admin or owner_id in an input model the client controls.

From PHP

Input models are FormRequest rules plus a DTO in one class. response_model is an API Resource / $hidden, applied automatically. Mass-assignment risk is the same as Eloquent's $fillable: only put allowed fields on the input model.
