A sensor is only useful in the house once it's on the network. This lesson gets a board onto Wi-Fi and publishing MQTT to the leaf on jarvis, and keeps it there when the router restarts. It builds on the MQTT course: client IDs, keepalive, wills.

Joining Wi-Fi

import network, time

def wifi(ssid, password, timeout_s=20):
    wlan = network.WLAN(network.STA_IF)
    wlan.active(True)
    if not wlan.isconnected():
        wlan.connect(ssid, password)
        start = time.ticks_ms()
        while not wlan.isconnected():
            if time.ticks_diff(time.ticks_ms(), start) > timeout_s * 1000:
                raise OSError("wifi timeout")
            time.sleep_ms(200)
    return wlan

Always with a timeout: a board that waits forever for a router that's rebooting is a board that needs unplugging. Keep the password out of main.py: a small secrets.py on the board, never in git.

MQTT with umqtt

from umqtt.simple import MQTTClient
import machine, binascii

cid = "fridge-" + binascii.hexlify(machine.unique_id()).decode()   # stable and unique
c = MQTTClient(cid, "192.168.1.20", user="fridge", password=PW, keepalive=60)
c.set_last_will(b"home/kitchen/fridge/status", b"offline", retain=True, qos=1)
c.connect()
c.publish(b"home/kitchen/fridge/status", b"online", retain=True, qos=1)
c.publish(b"home/kitchen/fridge/temp", b"4.2", retain=True)

umqtt.simple is small and does exactly what you call: it doesn't send keepalive pings by itself (call c.ping() within the keepalive, or publish often enough) and doesn't reconnect. To receive, c.set_callback(f), subscribe, and call c.check_msg() in your loop. umqtt speaks MQTT 3.1.1, which is what the NATS leaf wants. If import umqtt.simple fails, mpremote mip install umqtt.simple.

Staying connected

def run():
    delay = 1
    while True:
        try:
            wifi(SSID, WIFI_PW)
            c = connect_mqtt()          # will, birth, subscribe
            delay = 1
            while True:
                publish_reading(c)
                c.check_msg()
                time.sleep(30)
        except OSError as e:            # Wi-Fi or socket gone
            print("lost:", e)
            time.sleep(delay)
            delay = min(delay * 2, 300)

The same loop as aiomqtt's: connect, subscribe, work, and on any network error back off and start again from Wi-Fi. For an asyncio program, Peter Hinch's mqtt_as library does all of this (Wi-Fi outages included) and is worth using once the device does more than publish.

Addresses

A hostname like jarvis may not resolve from the board (no mDNS by default, no tailnet). Use the Pi's LAN address, and give the Pi a fixed lease on the router so it doesn't move.

From MQTT

Everything from the MQTT course applies at its strictest here: a stable client ID from the chip's id, a retained will and birth, subscriptions after every connect, QoS 1 for commands, target states not toggles. The device is the client those lessons were written for.

Trap

A while not wlan.isconnected(): pass with no timeout and no sleep. When the router's down at boot, the board spins forever, never reaching the code that would retry or report.

Try it

Run a local broker on your Mac and get the board publishing its uptime every 10 s, with a will. Restart your Wi-Fi router (or turn off the Mac's broker) and watch it come back on its own.
