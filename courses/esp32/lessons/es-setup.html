Getting from a new board to a Python prompt on it: install the firmware once, then copy files and type at the REPL. Two tools do all of it: esptool to write firmware, mpremote to talk to MicroPython.

The USB connection

Plug it in and a serial port appears: /dev/cu.usbserial-* or /dev/cu.usbmodem* on the Mac. Boards with a separate USB-serial chip (CP2102, CH340) show the first; S3 and C3 boards using the chip's own USB show the second. No port at all usually means a charge-only cable.

Flashing MicroPython

pip install esptool mpremote             # or: uv tool install esptool; uv tool install mpremote
esptool.py --chip esp32c3 erase_flash
esptool.py --chip esp32c3 write_flash -z 0x0 ESP32_GENERIC_C3-v1.xx.bin

Download the firmware for your exact chip from micropython.org; its page gives the flash offset (0x1000 for the original ESP32, 0x0 for S3 and C3). Erase first when switching from other firmware.

Boot mode

To accept new firmware, the chip must start in its download mode, which happens when GPIO0 (GPIO9 on the C3) is held low at reset. Most dev boards do it for you through the USB-serial lines. When esptool says it can't connect, do it by hand: hold BOOT, press and release RESET (EN), release BOOT, run the command again.

The REPL

mpremote                       # connects to the first board it finds, opens the REPL
>>> import machine, sys
>>> sys.implementation
>>> machine.freq()
240000000

Ctrl-] leaves mpremote. In the REPL: Ctrl-C stops a running program, Ctrl-D soft-resets (restarts MicroPython and runs main.py).

Files on the board

mpremote ls                    # the board's little filesystem, in its flash
mpremote cp main.py :main.py   # ":" is the board
mpremote run test.py           # run a file from the Mac without copying it
mpremote mip install umqtt.simple

At power-up MicroPython runs boot.py, then main.py. Keep boot.py nearly empty, put the program in main.py, and develop with mpremote run, so a broken main.py never stops you getting back in.

From Python

Same language, small standard library: time, json, os, asyncio exist, but trimmed; there's no pip at run time, no threads to rely on and no requests. machine, network and esp32 are the new modules.

Trap

A main.py that loops forever without a pause, or crashes into a reset loop, makes the board hard to reach. Ctrl-C in the REPL usually stops it; if not, erase the flash and start again. Add a 2-second sleep at the top of main.py while developing.

Try it

Flash MicroPython, open the REPL, and print machine.unique_id() as hex. You'll use it as the board's MQTT client ID.
