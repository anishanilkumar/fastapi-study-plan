For a device that's a standard sensor or switch, writing firmware is the slow way. ESPHome turns a YAML description into firmware, flashes it, and updates it over Wi-Fi from then on. Most ESP32s in a house are best done this way; MicroPython is for the ones that aren't standard.

A whole fridge sensor

esphome:
  name: fridge
esp32:
  board: esp32-c3-devkitm-1

wifi:
  ssid: !secret wifi_ssid
  password: !secret wifi_password
logger:
ota:
  - platform: esphome
    password: !secret ota_password

mqtt:
  broker: 192.168.1.20             # jarvis
  username: fridge
  password: !secret mqtt_password
  topic_prefix: home/kitchen/fridge

one_wire:
  - platform: gpio
    pin: GPIO4
sensor:
  - platform: dallas_temp
    name: Temperature
    update_interval: 60s
uv tool install esphome
esphome run fridge.yaml            # build, flash over USB the first time, then show the logs

It publishes home/kitchen/fridge/sensor/temperature/state, keeps a retained home/kitchen/fridge/status with a will, and announces itself to Home Assistant through MQTT discovery. secrets.yaml holds the passwords, and stays out of git.

OTA

After the first flash over USB, esphome run fridge.yaml finds the device on the network and updates it over Wi-Fi, so a sensor stuck in the fridge never needs unplugging. The OTA password stops anyone else on the LAN flashing it.

MQTT or the native API

ESPHome usually talks to Home Assistant over its own API instead of MQTT. Use api: if Home Assistant is the only consumer; use mqtt: (as here) when the house's programs should see it too, through the leaf and NATS. You can have both.

When MicroPython instead

ESPHomeMicroPython
Standard sensors, switches, lights, displaysOdd logic: a state machine, a protocol ESPHome doesn't know
OTA, Wi-Fi reconnects, MQTT, deep sleep handled for youYou write all of that (this course)
Change YAML, rebuild (a minute)Edit, mpremote run, see it (seconds)

A good path: learn on MicroPython (you see every step), then build the devices that stay in the house with ESPHome, and keep MicroPython for the ones it can't do. ESPHome's lambda: blocks of C++ and custom components close much of the gap.

From Nix

The same idea as your NixOS configs: declare what the device is, let a tool build it, redeploy by running one command. The YAML is the source of truth; keep it in git (without secrets.yaml).

Trap

Leaving out ota: on the first flash. The device works, but every later change means taking it out of wherever it's mounted and plugging in USB.

Try it

Flash the fridge YAML to a board on your desk, against a local broker, and watch its topics with mosquitto_sub -t 'home/#' -v. Change update_interval and update it over the air.
