To the broker, a payload is bytes: up to 256 MB, no type, no schema. Everything a subscriber needs to understand it is a convention between you and yourself, so write the convention down and keep it.

Plain value or JSON

home/kitchen/fridge/temp     4.2                                  # one value per topic
home/kitchen/fridge/state    {"temp": 4.2, "door": "closed", "ts": 1763000000}   # one object

A plain value per topic is easy to read in mosquitto_sub and easy for any device to publish. A JSON object keeps related values together and in step (the temperature and the door at the same moment), and has room for a timestamp. Both are fine; mixing them on one topic is not. Zigbee2MQTT uses one JSON object per device, Tasmota a mix.

Say what the numbers are

  • Units in the name or the schema, never only in your head: temp_c, or {"temp": 4.2, "unit": "°C"}.
  • Timestamps in UTC, as seconds since the epoch or ISO 8601 with an offset. A retained value without a time can't tell you it's three days old.
  • Booleans and states as words that can't be misread: "ON"/"OFF", "open"/"closed". A bare 1 could be a count.

Commands and state are different messages

home/hall/light/power/set   ON       # what someone wants      (not retained)
home/hall/light/power       ON       # what the light reports  (retained)

The light subscribes to /set, acts, then publishes what it actually did. The dashboard shows the state topic, so a command the light ignored or couldn't carry out shows as not done. Send the target state, not a toggle, so a repeated command (QoS 1) changes nothing.

Decode defensively

def on_message(client, userdata, msg):
    try:
        data = json.loads(msg.payload)
        temp = float(data["temp"])
    except (ValueError, KeyError, TypeError):
        log.warning("bad payload on %s: %r", msg.topic, msg.payload[:200])
        return
    ...

Anything with access to the topic can publish anything to it, including a device with new firmware that renamed a field. One bad message must cost one log line, not the subscriber: an exception that escapes a callback can stop a client's network loop (lesson 9).

Keep payloads small

MQTT is for state and events. A camera snapshot, a firmware image or a PDF goes on HTTP or a file store; the MQTT message says "a new snapshot is at this URL". It's the same rule as the household's NATS subjects: messages are announcements, content stays on each app's own HTTPS API.

From HTTP

HTTP has Content-Type; MQTT 3.1.1 has nothing (MQTT 5 adds a content type and a "payload is UTF-8" flag). The topic is the only place to say what the bytes mean, so one topic, one format.

Trap

msg.payload is bytes. if msg.payload == "ON": is never true in Python 3; compare with b"ON" or decode first.
