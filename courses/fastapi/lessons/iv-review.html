The live round is a code review. This is a routine to follow under pressure, a checklist of what to look for, and a worked example.

The routine

  1. Read all of it first. Say what the code is meant to do in one sentence before criticising anything.
  2. Worst bug first, with a concrete scenario: "if two requests register the same serial at once, both pass the check and we get duplicates".
  3. The fix, in code or precise words.
  4. The test that would catch it, and what that test can't prove.
  5. Then rank the rest: security and data loss, then correctness, then performance, then style. Say which you'd block a merge on.

Worked example

db = SessionLocal()
cache = {}

@app.post("/devices")
async def register(serial: str, owner_id: int, key: str = Header()):
    if key == API_KEY:
        if db.query(Device).filter(Device.serial == serial).first():
            return {"error": "exists"}
        d = Device(serial=serial, owner_id=owner_id,
                   registered=datetime.now())
        db.add(d); db.commit()
        cache[serial] = d
        requests.post(WEBHOOK, json={"serial": serial})
        return d

Cover the answer and find at least eight issues before reading on.

  1. Shared session (db at module level): shared across requests; one failed commit breaks it for everyone. Fix: get_db with yield, via Depends.
  2. Blocking calls in async def: sync DB queries and requests.post freeze the loop; the webhook has no timeout. Fix: plain def (or async client and session), timeout, ideally a background task or queue.
  3. Race on registration: check-then-insert. Fix: unique constraint, catch IntegrityError, return 409.
  4. Wrong status codes: "exists" returns 200; a wrong key returns 200 with null. Fix: 409, and 401.
  5. Timing-unsafe key comparison: ==. Fix: hmac.compare_digest, and fail closed if API_KEY is empty.
  6. owner_id from the client: anyone with the key registers devices to anyone. Fix: derive the owner from the authenticated identity.
  7. Naive datetime.now(). Fix: datetime.now(timezone.utc).
  8. Unbounded module-level cache holding ORM objects detached from a session; inconsistent across workers. Fix: drop it or use a bounded cache keyed on plain data.
  9. No response model: returns the ORM object directly. Fix: -> DeviceOut, status_code=201.
  10. Params as query strings on a POST; no validation of serial. Fix: a Pydantic body with a pattern.

Worst first: I'd lead with the shared session plus blocking calls (it takes the service down under load), or the owner_id trust (security), and say why I ranked it there.

When you're unsure of syntax

"In PHP I'd do X. I'd check the docs for the exact Python API, but the fix is Y." Judgement is what's scored; docs are allowed.
