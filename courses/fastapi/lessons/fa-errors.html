The status code is part of the API's contract. Interviewers notice wrong ones, and leaking internals in error bodies.

Raising HTTP errors

from fastapi import HTTPException, status

@app.get("/devices/{device_id}")
def get_device(device_id: int, db: DB, user: CurrentUser) -> DeviceOut:
    device = db.get(Device, device_id)
    if device is None or device.owner_id != user.id:
        raise HTTPException(status.HTTP_404_NOT_FOUND, "device not found")
    return device

Raising (not returning) stops the handler; FastAPI sends {"detail": "device not found"}.

Which code

CodeMeaning
200 / 201 / 204OK / created (POST that made something) / no content (DELETE)
400Bad request your validation couldn't express as a schema
401Not authenticated: missing or invalid credentials. Send WWW-Authenticate.
403Authenticated, but not allowed
404Not found, or exists but belongs to someone else (don't reveal it exists)
409Conflict with current state: duplicate serial, version mismatch
422Body/params failed validation (FastAPI sends this for you)
429Rate limited
500Your bug. Never raise it on purpose.
502 / 503 / 504Upstream failed / you're unavailable / upstream timed out

Setting success codes

@app.post("/devices", status_code=201)
def create_device(body: DeviceIn) -> DeviceOut: ...

@app.delete("/devices/{device_id}", status_code=204)
def delete_device(device_id: int) -> None: ...

Upstream failures

try:
    r = await client.get(VENDOR, timeout=5)
    r.raise_for_status()
except httpx.TimeoutException:
    raise HTTPException(504, "vendor timed out")
except httpx.HTTPError:
    log.exception("vendor call failed")
    raise HTTPException(502, "vendor unavailable")

Log the details server-side; give the client a short, safe message. Never put tracebacks, SQL or secrets in detail.

Custom exception handlers

class DeviceNotFound(Exception): ...

@app.exception_handler(DeviceNotFound)
async def not_found(request, exc):
    return JSONResponse(status_code=404, content={"detail": "device not found"})

Lets your service layer raise domain exceptions without importing FastAPI.

Trap

return HTTPException(404) instead of raise sends a 200 with a weird body. And catching Exception around a block that raises HTTPException swallows your own 404.

From PHP

abort(404) / throw new NotFoundHttpException() → raise HTTPException(404). Laravel's exception handler render() → @app.exception_handler.
